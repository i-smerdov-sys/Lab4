# Лабораторная работа №4. Ансамбли и полносвязные нейронные сети

## Данные и подготовка

Использован набор German Credit: 1000 наблюдений,
20 входных признаков и целевой столбец `Creditability`.

В предоставленном файле данные разделены точкой с запятой.

Целевая переменная бинарная:
- 1 — положительный класс (700 объектов);
- 0 — отрицательный класс (300 объектов).

Данные разделены на обучающую и тестовую части
в пропорции 80/20 с помощью train_test_split:

- test_size=0.2;
- stratify=y;
- random_state=42.

Стратификация сохраняет приблизительное соотношение
классов в обеих частях.

Пропусков в исходном датасете не обнаружено.
Все 20 признаков представлены числами.

Категориальные признаки в German Credit закодированы
целыми числами. В экспериментах с деревьями эти коды
оставлены числовыми, без стандартизации.

Для устойчивости к возможным пропускам в конвейере
модели добавлено заполнение медианой.

Для MLP использовалась отдельная предобработка:
стандартизация трёх количественных признаков
и one-hot-кодирование остальных признаков.

Преобразования обучаются внутри конвейера
только на соответствующей обучающей выборке.

## Гипотезы и эксперименты

Проверялась гипотеза, что ансамбли деревьев будут
лучше подходить для небольшого табличного набора
с нелинейными зависимостями, чем полносвязная MLP.

Проведено сравнение моделей:

- Random Forest — ансамбль деревьев,
  использующий бэггинг и случайный выбор признаков.

- Extra Trees — ансамбль деревьев с более случайным
  выбором порогов разделения.

- Gradient Boosting — последовательное обучение
  деревьев для исправления ошибок предыдущих моделей.

- HistGradientBoosting — вариант градиентного бустинга
  с гистограммным разбиением признаков.

- MLPClassifier — полносвязная нейронная сеть
  с двумя скрытыми слоями (64 и 32 нейрона).

Для предварительного сравнения использовалась
стратифицированная 5-блочная кросс-валидация
только на обучающей части.

Основной критерий выбора — средний ROC-AUC
на кросс-валидации.

Тестовая часть не использовалась для выбора
гиперпараметров или модели.

## Метрики

Для оценки использовались следующие метрики:

- ROC-AUC — качество ранжирования объектов
  по вероятности положительного класса;
- Accuracy — доля правильных предсказаний;
- Precision — точность положительных предсказаний;
- Recall — полнота обнаружения положительного класса;
- F1 — гармоническое среднее Precision и Recall.

ROC-AUC рассчитывался по вероятностям
положительного класса, а не по бинарным меткам.

Порог для получения бинарных предсказаний — 0.5.

| Модель | CV ROC-AUC, среднее | CV ROC-AUC, std |
|---|---:|---:|
| Extra Trees | 0.7777 | 0.0357 |
| Random Forest | 0.7765 | 0.0343 |
| HistGradientBoosting | 0.7660 | 0.0218 |
| Gradient Boosting | 0.7633 | 0.0389 |
| MLPClassifier | 0.7500 | 0.0264 |

На тестовой части для выбранных конфигураций
получены следующие результаты:

| Модель | Test ROC-AUC | Accuracy | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|
| Random Forest | 0.8326 | 0.7750 | 0.8276 | 0.8571 | 0.8421 |
| Extra Trees | 0.8192 | 0.7550 | 0.8421 | 0.8000 | 0.8205 |
| Gradient Boosting | 0.8300 | 0.7700 | 0.7901 | 0.9143 | 0.8477 |
| MLPClassifier | 0.8145 | 0.7750 | 0.8322 | 0.8500 | 0.8410 |

## Выбранная модель

Выбрана модель Extra Trees.

Она использует 250 деревьев, параметр
min_samples_leaf=3, max_features="sqrt"
и class_weight="balanced".

По среднему ROC-AUC кросс-валидации
модель показала лучший результат среди
проверенных вариантов.

На тестовой части ROC-AUC составил 0.8192,
что выше порога 0.80.

В ensemble_models.py модель обучается только
на train_features и train_target.

Вероятности положительного класса извлекаются
с помощью predict_proba.

Бинарные предсказания формируются порогом 0.5.

test_target используется только после получения
предсказаний для вычисления метрик.

## Выводы и ограничения

Ансамбли деревьев показали более высокий
средний ROC-AUC в кросс-валидации, чем MLP
в выбранных конфигурациях.

Extra Trees оказался лучшим по критерию выбора,
хотя различие с Random Forest невелико.

Gradient Boosting показал высокий Recall
на тестовой части.

Тестовый ROC-AUC зависит от конкретного разбиения.
На небольшом датасете из 1000 строк результат
одного разбиения не гарантирует такого же качества
на новых выборках.

Коды категориальных признаков в деревьях
трактуются как числовые значения. Это может
навязывать порядок категориям, для которых
он не всегда содержательно оправдан.

Исследовались ограниченные наборы гиперпараметров,
поэтому найденная модель не является гарантированно
глобально оптимальной.

Для более надёжной оценки потребовалась бы
повторная или вложенная кросс-валидация.

## Воспроизводимость

Для воспроизводимости экспериментов использовались:

- random_state = 42;
- разбиение 80% train / 20% test;
- stratify=y;
- StratifiedKFold с 5 блоками;
- shuffle=True;
- random_state=42 для кросс-валидации.

Контрактная функция запускается проверяющей
системой через run_ensemble_experiment(data).

Она не читает файл самостоятельно и использует
переданные ей train/test части.
